## 1. Парсинг резюме (PDF / DOCX / HTML / сканы)

### Кандидаты

**1) unstructured**
**2) docling**
**3) pymupdf**
(+ OCR слой)

### Рекомендация (комбинация, не выбор одного)

**Базовый стек:**

* **unstructured** — основной
* **pymupdf** — fallback + контроль
* **OCR (tesseract / paddleocr)** — отдельно

### Почему

**unstructured**

* Поддерживает PDF, DOCX, HTML, email
* Уже оптимизирован под LLM-пайплайны
* Делит документ на логические блоки (sections, tables)
  − Медленный
  − Иногда «галлюцинирует структуру»

**pymupdf**

* Быстрый
* Максимальный контроль над текстом
* Минимум магии
  − Нет семантики (ты сам решаешь, что есть что)

**docling**

* Интересный, но **ещё нестабилен**
* Меньше battle-tested
  → **не бери в критический прод сейчас**

**Итого архитектурно правильно:**

```
PDF/DOCX
 ├─ unstructured → structured chunks
 ├─ pymupdf → raw text fallback
 └─ OCR → если confidence < threshold
```

Добавь:

* **confidence score парсинга**
* лог сохранения *исходного текста* (для аудита)

## 2. Embeddings + Vector DB

### Qdrant — ✅ правильный выбор

* Open-source
* Filters + payloads
* Хорошо масштабируется
* Отлично работает с LlamaIndex

### Embeddings

На старте:

* `text-embedding-3-small` (если допустим API)
* или **bge-small / bge-base** (локально)

Архитектурно:

* **versioned embeddings**
* один резюме → несколько embedding-версий

```
resume_id
 ├─ embedding_v1_bge
 ├─ embedding_v2_openai
```

Это критично для сравнения качества.

## 4. Guardrails / Outlines

### Verdict

* **Outlines — для строгих структур**
* **Guardrails — для бизнес-валидаций**

### Рекомендация

Используй **оба**, но:

* **Outlines** → JSON / Pydantic
* **Guardrails** → semantic rules

Пример:

* Outlines гарантирует:

```json
{
  "skills": [],
  "experience_years": int
}
```

* Guardrails проверяет:
* experience_years ≥ 0
* skills ∈ taxonomy

## 5. LlamaIndex vs LangChain

### Коротко

👉 **LlamaIndex — твой выбор**

### Почему

**LlamaIndex**

* Лучше работает с retrieval / resume-подобными задачами
* Отличная интеграция с Qdrant
* Query Engine abstractions
* Меньше «магии», чем LangChain

**LangChain**
− Слишком обширный
− Часто ломается при апдейтах
− Сложно дебажить одному

### Архитектура

* LlamaIndex = core RAG
* Свои сервисы вокруг него
